# Bundled ML Model Setup

Clio ships two CoreML models as app resources, generated from public
HuggingFace checkpoints via one-time, dev-time-only Python conversion
scripts. Neither the conversion scripts nor any Python runtime ship in the
app — only the resulting `.mlmodelc`/model-folder output does.

**These model directories are gitignored** (see `.gitignore`) — they are
large (~3.4GB combined), fully reproducible build artifacts, not source
code. A fresh clone of this repo will not have them; you must generate
them locally before building/running the app. Xcode will fail at build
time (missing resources) or the app will report the transcription/
anonymization model as unavailable at runtime until you do this.

## 1. NB-Whisper-large (transcription — WhisperKit)

Converts the official `NbAiLab/nb-whisper-large` weights to WhisperKit's
CoreML format using Argmax's `whisperkittools`.

```bash
python3.11 -m venv /tmp/model-convert-venv
source /tmp/model-convert-venv/bin/activate
pip install --upgrade pip

git clone --depth 1 https://github.com/argmaxinc/whisperkittools.git /tmp/whisperkittools
cd /tmp/whisperkittools
pip install -e .

whisperkit-generate-model \
  --model-version NbAiLab/nb-whisper-large \
  --output-dir /tmp/whisper-output
```

This produces `MelSpectrogram.mlmodelc`, `AudioEncoder.mlmodelc`, and
`TextDecoder.mlmodelc` under
`/tmp/whisper-output/NbAiLab_nb-whisper-large/`. Copy them into the app's
resources:

```bash
mkdir -p Resources/WhisperKitModels/NbAiLab_nb-whisper-large
cp -R /tmp/whisper-output/NbAiLab_nb-whisper-large/MelSpectrogram.mlmodelc \
      /tmp/whisper-output/NbAiLab_nb-whisper-large/AudioEncoder.mlmodelc \
      /tmp/whisper-output/NbAiLab_nb-whisper-large/TextDecoder.mlmodelc \
      Resources/WhisperKitModels/NbAiLab_nb-whisper-large/
```

WhisperKit also needs the tokenizer files (fetched directly from the HF
repo, not generated by `whisperkittools`):

```bash
mkdir -p Resources/WhisperKitModels/NbAiLab_nb-whisper-large/tokenizer
cd Resources/WhisperKitModels/NbAiLab_nb-whisper-large/tokenizer
for f in tokenizer.json tokenizer_config.json vocab.json merges.txt \
         added_tokens.json special_tokens_map.json generation_config.json config.json; do
  curl -fsSL "https://huggingface.co/NbAiLab/nb-whisper-large/resolve/main/$f" -o "$f"
done
```

`NativeTranscriptionEngine.swift` looks these up via
`Bundle.main.url(forResource: "NbAiLab_nb-whisper-large", withExtension: nil, subdirectory: "WhisperKitModels")`.

## 1b. NB-Whisper-large-verbatim (optional — "Ordrett" transcription mode)

`NbAiLab/nb-whisper-large-verbatim` is a **separate model checkpoint**
(fine-tuned 200-250 additional steps from the main model above by NB
AI-Lab specifically to preserve fillers, hesitations, and false starts
literally, lower-cased and without punctuation correction) — not a
decode-time flag on the main model. This is why the "Ordrett" (verbatim)
setting in Transkripsjon-innstillinger needs its own bundled model to
actually do anything; without it, `NativeTranscriptionEngine` transparently
falls back to the clean model and logs a warning.

**This model has not been converted/bundled as of this writing** — it was
lost when the app moved from the Python `no-transcribe` subprocess (which
switched between two model checkpoints for renset/verbatim) to the native
WhisperKit port (which only ever bundled the clean checkpoint). Converting
it follows the exact same recipe as §1, substituting the verbatim repo:

```bash
# (reuse the venv/whisperkittools checkout from §1)
whisperkit-generate-model \
  --model-version NbAiLab/nb-whisper-large-verbatim \
  --output-dir /tmp/whisper-output

mkdir -p Resources/WhisperKitModels/NbAiLab_nb-whisper-large-verbatim
cp -R /tmp/whisper-output/NbAiLab_nb-whisper-large-verbatim/MelSpectrogram.mlmodelc \
      /tmp/whisper-output/NbAiLab_nb-whisper-large-verbatim/AudioEncoder.mlmodelc \
      /tmp/whisper-output/NbAiLab_nb-whisper-large-verbatim/TextDecoder.mlmodelc \
      Resources/WhisperKitModels/NbAiLab_nb-whisper-large-verbatim/

mkdir -p Resources/WhisperKitModels/NbAiLab_nb-whisper-large-verbatim/tokenizer
cd Resources/WhisperKitModels/NbAiLab_nb-whisper-large-verbatim/tokenizer
for f in tokenizer.json tokenizer_config.json vocab.json merges.txt \
         added_tokens.json special_tokens_map.json generation_config.json config.json; do
  curl -fsSL "https://huggingface.co/NbAiLab/nb-whisper-large-verbatim/resolve/main/$f" -o "$f"
done
```

`NativeTranscriptionEngine.isVerbatimBundled` reflects whether this second
model folder is present; once bundled, the "Ordrett" setting will actually
switch to it instead of silently using the clean model.

## 2. NbAiLab/nb-bert-base-ner (anonymization — BERT NER)

Converts the official `NbAiLab/nb-bert-base-ner` weights to a CoreML
`.mlpackage` via `coremltools`, using pinned versions confirmed compatible
this session (`transformers==4.46.3`, `torch==2.7.0`; newer versions of
either produced tracing/conversion errors during model-conversion testing).

```bash
python3.11 -m venv /tmp/bert-convert-venv
source /tmp/bert-convert-venv/bin/activate
pip install --upgrade pip
pip install coremltools "transformers==4.46.3" "torch==2.7.0" \
  --extra-index-url https://download.pytorch.org/whl/cpu
```

Save the following as `/tmp/convert_bert_ner.py`:

```python
import coremltools as ct
import torch
from transformers import AutoTokenizer, AutoModelForTokenClassification, AutoConfig

MODEL_NAME = "NbAiLab/nb-bert-base-ner"
MAX_TOKENS = 512
OUT_PATH = "/tmp/NBBertNER.mlpackage"

tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)
config = AutoConfig.from_pretrained(
    MODEL_NAME, torchscript=True, return_dict=False, attn_implementation="eager"
)
# IMPORTANT: AutoConfig resolves max_position_embeddings=1200 for this repo
# (stale upstream default), but the actual checkpoint tensor is 512 —
# forcing this to the true checkpoint shape is required, otherwise the
# entire position-embedding matrix silently loads as random noise instead
# of the real trained weights (confirmed via a real inference diff test).
config.max_position_embeddings = 512
model = AutoModelForTokenClassification.from_pretrained(MODEL_NAME, config=config)
model.eval()

dummy_input_ids = torch.randint(0, tokenizer.vocab_size, (1, MAX_TOKENS))
dummy_attention_mask = torch.ones((1, MAX_TOKENS), dtype=torch.long)
dummy_token_type_ids = torch.zeros((1, MAX_TOKENS), dtype=torch.long)
traced = torch.jit.trace(model, (dummy_input_ids, dummy_attention_mask, dummy_token_type_ids))

mlmodel = ct.convert(
    traced,
    inputs=[
        ct.TensorType(name="input_ids", shape=(1, ct.RangeDim(1, MAX_TOKENS)), dtype=int),
        ct.TensorType(name="attention_mask", shape=(1, ct.RangeDim(1, MAX_TOKENS)), dtype=int),
        ct.TensorType(name="token_type_ids", shape=(1, ct.RangeDim(1, MAX_TOKENS)), dtype=int),
    ],
    outputs=[ct.TensorType(name="logits")],
    minimum_deployment_target=ct.target.macOS14,
    compute_units=ct.ComputeUnit.ALL,
    # IMPORTANT: without forcing FLOAT32, ANE-dispatched ops can silently
    # produce NaN logits on real hardware even though the conversion
    # itself succeeds without error (confirmed via a real inference test).
    compute_precision=ct.precision.FLOAT32,
    convert_to="mlprogram",
)
mlmodel.save(OUT_PATH)
tokenizer.save_pretrained("/tmp/NBBertNER-tokenizer")
```

```bash
python /tmp/convert_bert_ner.py

# Pre-compile to .mlmodelc (BertNERDetector.swift loads the compiled form
# directly — this also avoids requiring on-device compilation at first launch)
xcrun coremlcompiler compile /tmp/NBBertNER.mlpackage /tmp/
```

Copy into the app's resources:

```bash
cp -R /tmp/NBBertNER.mlmodelc Resources/NBBertNER.mlmodelc
mkdir -p Resources/NBBertNER-tokenizer
cp /tmp/NBBertNER-tokenizer/vocab.txt Resources/NBBertNER-tokenizer/vocab.txt
```

`BertNERDetector.swift` looks these up via
`Bundle.main.url(forResource: "NBBertNER", withExtension: "mlmodelc")` and
`Bundle.main.url(forResource: "vocab", withExtension: "txt", subdirectory: "NBBertNER-tokenizer")`.

## Verifying the setup

After copying both models into `Resources/`, a real Xcode build
(`xcodebuild -project Clio.xcodeproj -scheme Clio build`, not just
`swift build`) will bundle them into the `.app` — confirm with:

```bash
ls "$(xcodebuild -showBuildSettings 2>/dev/null | awk -F'= ' '/BUILT_PRODUCTS_DIR/{print $2; exit}')/Clio.app/Contents/Resources/" \
  | grep -E "WhisperKitModels|NBBertNER"
```

At runtime, `NativeTranscriptionEngine.isBundled` and
`BertNERDetector.isAvailable` reflect whether both models loaded
successfully — both are also exercised at startup via
`SystemRequirementChecker.checkNativeModels()` and
`DependencyManager`'s `.transcriptionModel`/`.anonymizerModel` checks.
